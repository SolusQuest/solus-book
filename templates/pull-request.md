# Pull request template

Use the project's actual template when required. Otherwise adapt the sections below under [PR workflow](../standards/pr-workflow.md), removing instructional text and irrelevant sections.

## Summary

Explain the concrete problem and resulting behavior for a reviewer who has not seen the conversation. Include a short before/after example when it helps.

## Tracking

Reference the owning issue or record. For a bounded no-issue change, give a brief reason separate tracking adds no value.

## Validation

State checks actually executed, relevant inputs and results, and material limits. Separate local evidence from CI and review. Identify blocked or unexecuted required checks.

## Compatibility and remaining work

Describe actual consumer impact, breaking behavior, unresolved findings, or decisions relevant to acceptance. Omit this section if none apply.
